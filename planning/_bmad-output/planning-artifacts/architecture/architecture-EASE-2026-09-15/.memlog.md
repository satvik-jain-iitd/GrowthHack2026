- (decision) LLM boundary per AI/ML Prescriptive ADR: the two narrow LLM call sites (FR-1 intent to Journey resolution; FR-2 screen-state to Step inference) go through one isolated, stateless, real-time OLTP-shaped service boundary (Safechain-pattern: FastAPI-style microservice), never scattered inline calls. AIDA (OLAP/batch/no-code) is not a fit and is rejected. This keeps the LLM swappable per the brief's 'buy the rails' stance and matches officially supported GrowthHack models (Azure GPT 5.2 / LLAMA 3.2-3.3).
- (decision) Data shape split per Database Prescriptive ADR: Journey definitions + Micro-Guide lifecycle state (pending_review/approved/rejected) are relational (ACID, workflow correctness) -- embedded SQLite for demo. Telemetry Events are an append-only, schema-flexible event log (document/time-series shaped, OTel-compatible field names: timestamp, event_type, journey_id, step, attributes) -- JSON Lines file for demo, reshape-free path to a real event store later.
- (decision) Observability per Application-Observability ADR: demo emits lightweight structured JSON telemetry only (no ELF/OTel wiring for a single mocked demo) but every event's field names/shapes are chosen to be OTel-semantics-compatible so a later production build can feed ELF without a schema rewrite. Deviation from full ELF/OTel documented here per the ADR's own exception-documentation expectation.
