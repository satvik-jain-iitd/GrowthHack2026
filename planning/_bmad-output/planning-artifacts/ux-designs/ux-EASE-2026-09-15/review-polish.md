# Structure & Prose Polish Review — EASE UX Spines

## Structure findings
- **[medium]** Foundation is doing too many jobs in one uninterrupted block (EXPERIENCE.md / Foundation). *Fix:* Split it into short labeled sub-blocks such as Platform, Scope boundary, Guardrails, and Prototype relationship so readers can locate constraints quickly.
- **[medium]** Information Architecture loses scanability after the core table because glossary and process notes are appended as body prose (EXPERIENCE.md / Information Architecture). *Fix:* Keep the surface map as the main artifact, then move the glossary and composition-reference material into clearly labeled sub-blocks beneath it.
- **[medium]** State Patterns bundles owner-flow states and Specialist Review lifecycle states into one long, undifferentiated table (EXPERIENCE.md / State Patterns). *Fix:* Separate the content into grouped subsections or two smaller tables so each persona's state model can be scanned independently.
- **[low]** Colors combines token inventory, contrast guidance, and avoidance rules in one continuous section (DESIGN.md / Colors). *Fix:* Add internal subheads or a compact schema such as Chrome Layer, Host App Skin, Contrast, and Avoid so readers can jump directly to the needed guidance.
- **[low]** Components mixes visual specification with behavioral caveats, which blurs the handoff boundary between the two spines (DESIGN.md / Components). *Fix:* Use a consistent mini-pattern per component: visual spec first, then a brief explicit cross-reference for behavioral rules.
- **[low]** Inline `[ASSUMPTION]` / `[NOTE]` markers are frequent enough to interrupt reading rhythm and weaken scannability (both files / multiple sections). *Fix:* Standardize them as short trailing notes or separate callout bullets at the end of the relevant subsection.

## Prose findings
- **[medium]** Several sentences stack the main rule, its rationale, and multiple caveats into one long line (DESIGN.md / Brand & Style; EXPERIENCE.md / Foundation, Component Patterns, Key Flows). *Fix:* Split these into a lead sentence plus one shorter support sentence, and move citations or caveats to the end where possible.
- **[medium]** The spec voice occasionally shifts into pitch language, which makes the tone less consistent in normative sections (DESIGN.md / Colors, Do's and Don'ts; EXPERIENCE.md / State Patterns, Key Flows). *Fix:* Keep vivid language inside example UI copy, but use a steadier, more neutral voice for rules and behavior descriptions.
- **[low]** Terminology and hyphenation are not fully normalized for the same concepts (DESIGN.md / Brand & Style, Do's and Don'ts; EXPERIENCE.md / Foundation, Information Architecture). *Fix:* Pick one canonical form for terms like Host App Skin, host app, and host-app, then apply it consistently throughout both spines.
- **[low]** Parenthetical references and inline citations frequently compete with the main clause for attention (both files, especially DESIGN.md / Colors and EXPERIENCE.md / Component Patterns, State Patterns). *Fix:* Reduce parenthetical load by moving secondary references into short trailing clauses or a more consistent note pattern.
- **[low]** Some table cells read like compressed paragraphs rather than scan lines (EXPERIENCE.md / Component Patterns, State Patterns; DESIGN.md / Do's and Don'ts). *Fix:* Trim each cell to one principal rule plus one qualifier, or break secondary nuance into a short follow-on note.
- **[low]** Cross-document setup language is repeated in slightly different wording across the openings, which weakens the sense of a single editorial system (DESIGN.md / opening blockquote; EXPERIENCE.md / opening blockquote and Foundation). *Fix:* Reuse one concise standard sentence for the pairing and prototype-ground-truth caveat so both documents feel more unified.
