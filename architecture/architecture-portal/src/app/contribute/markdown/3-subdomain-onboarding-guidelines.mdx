# Subdomain Onboarding Guidelines

This document provides a comprehensive overview of the steps and best practices for onboarding a new subdomain to Architecture Portal.

## Step 1: Review Playbook Guide

Go through the [**_EA Design Playbook_**](https://GitHub.aexp.com/amex-eng/ea-design-playbook) and
[**_Getting Started with EA Playbook Guide_**](./getting-started) to learn how to setup your repository.

## Step 2: Onboarding Process

Requests can be submitted using the following form: [Subdomain Onboarding Request Form](https://architecture1.aexp.com/onboarding-form?type=d5864bda-607b-4116-a9e7-352cddb92181)

:::info

Requests can only be submitted by **_Band 40+_ users**.

:::

## Step 3: Approval Process

Unlike other onboardings, subdomains have a stricter approval process. Please refer to the following workflow to understand the process:

<img
    src='/how-to-contribute/subdomain-onboarding-workflow.png'
    alt='Subdomain Onboarding Workflow'
    style={{ maxWidth: '100%', height: 'auto' }}
/>

1. **Band 40+ member** submits request for subdomain onboarding.
2. Domain's **Enterprise Architect** then starts an email thread with the following stakeholders:
    - Requester
    - Portal Team: [architectureportalcoreteam@aexp.com](mailto:architectureportalcoreteam@aexp.com)
    - Domain Leaders: refer to the [Domain Owners View](https://architecture1.aexp.com/company-domains?view=ownerView)
        - Head Engineer
        - Principal Architect
    - Utsab Kayal: [utsab.kayal@aexp.com](mailto:utsab.kayal@aexp.com)
3. Domain's **Principal Architect** makes a decision on the request.
4. If approved, the **Enterprise Architect** will get approval from Utsab Kayal.
5. Once all approvals are received, the **Portal Team** will onboard the subdomain to the Architecture Portal.

    _Please be sure to keep the [Portal Team](mailto:architectureportalcoreteam@aexp.com) in the loop during the entire process._
