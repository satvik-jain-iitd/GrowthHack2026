1 The Mission & PitchWhy we exist · the one-liner · who we serve · what winning looks like ▸

One-sentence pitch

"EASE helps users stop learning how systems work — and start accomplishing what they came to do."

The shift we are proving

TO (EASE)

The demo beats (what judges see inside the tech act)

  1. Owner types "I want to get my restaurant live" → journey panel appears.
  2. EASE highlights each floor-plan action; deterministic validation ticks green.
  3. "Set weekday hours 5–11pm" → EASE Assist prepares the values → human confirms.
  4. Journey completes → a Scribe-like guide is auto-generated from the real path (the wow).
  5. EASE Studio shows the guide + friction telemetry → specialist approves → knowledge improves.

Production rules (protect the demo)

Always
  • Every LLM segment is pre-recorded
  • Live portion is deterministic UI only (no flaky AI on stage)
  • Record in rehearsal on the exact hero journey
Never
  • No live LLM dependency during recording
  • No real/PII data on screen (mock only)
  • No claims we can't back (governance capabilities = referenced, not built)

6 Technical Approach — With Options Kept OpenDecided vs open everywhere · every Amex unknown has a fallback ▸
Rule for this sprint We do not know the exact Amex-approved architecture yet. Every layer below has DECIDED vs OPTIONS OPEN markers. If one path is blocked, we take the next — nothing waits on a single unknown. Everything stays containerizable and portable.
LayerPrimary stanceStatusAlternatives
App framework Next.js (App Router) — huge OSS base, full-stack in one repo DECIDED Plain React SPA · Vite + React if we need pure static
Styling / UI Tailwind + shadcn/ui primitives on Amex design tokens (Benton Sans, Amex blue/green) DECIDED Radix only · MUI · Ant Design (Amex look must stay in control either way)
Highlighting / walkthrough Fork an OSS tour engine (Driver.js / Intro.js) or thin custom CDP overlay — Amex blocks browser extensions OPTIONS OPEN Shepherd.js · custom overlay via Chrome DevTools Protocol · Accessibility-API overlay (fallback)
Step capture (Scribe-like) Playwright / Puppeteer driven from the CDP companion app OPTIONS OPEN Pre-seeded screenshots injected (safe fallback) · in-app DOM snapshot
Journey knowledge Graph-backed model (page ↔ button ↔ API ↔ step) so "what's next" is deterministic + auditable — not plain RAG OPTIONS OPEN Neo4j Community · Apache AGE (Postgres) · lighter JSON-graph — decision after D1 spike
LLM Amex Launchpad (internal) for intent parsing — pre-recorded in demo OPTIONS OPEN Azure OpenAI-compatible · Llama · Gemini hosted — all swappable behind one interface
Agentic compatibility Expose EASE as an MCP server (get_journey_state, validate_step, capture_guide) via a Docker safety gateway OPTIONS OPEN MCP registry details drop 09-21 → adapt then; no MCP = still a full product demo
Hosting / deploy Containerized Next.js build — portable to whatever Amex approves OPTIONS OPEN Amex container platform · internal static host (static export path) · demo machine
Charts / insights Recharts or Tremor for the EASE Insights friction view OPTIONS OPEN Plain CSS bars (zero-dependency fallback)

Trust-by-design (this is a selling point, not overhead)

  • Companion app observes via CDP from outside the browser — never modifies the page. Compliance concern → trust story.
  • Human approves every published journey (no uncontrolled self-modification): Observe → Detect → Recommend → Human Validate → Improve.
  • Mock / PII-free data only; reference Launchpad redaction, safechain, substitution, local memory in the pitch as available capabilities.
